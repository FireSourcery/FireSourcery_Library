# PlannedItemBrief

**Level** — process: how deferred work is carried, not a shape in code.

**Force** — a block deferred for weeks loses its context: the reasons live in session logs, the owner's answers in
filled forms, the design in someone's head. Picked up later, the work starts with re-research, and the decisions that
were already made get re-asked. A plan that is prose alone also does not carry into implementation: the first coding
step re-derives the design.

**Shape and lifecycle** — the `/proposal` skill (owner's `workflow` plugin) holds both: one self-contained file per
block — **Status**, **Context**, **Design** (drawn), **Sketch**, **Done already**, **Open for you** (the owner's
boxes) — written when the block is deferred, the plan's seed at pickup, moved to the dated log when it lands.

**Here** — instances live in `Docs/Proposals/`, created with its first deferred block (named `planned/` until 2026-11-22); its `README.md` indexes every
entry with what each waits on. The app consumer keeps its own instances in its `doc/planned/`.

**Source** — none published; grown from this project's fill-out decision forms (2026-11-20) and their drift.
